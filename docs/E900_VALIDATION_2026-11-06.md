Scope: one user's E900, GlassX, and local macOS Swift/CoreBluetooth client. All times below are Asia/Taipei. Hardware and firmware revisions have not been independently identified. This report contains sanitized protocol evidence, not private images or peripheral identifiers.

Short UUIDs above use the standard Bluetooth base UUID. Do not use AE00 for these tests; its purpose on E900 is unconfirmed.

## Validated command frames

| Operation | Client→E900 hex | Observed response |
|---|---|---|
| Battery query | `AB 55 00 03 17 00 17` | `AC 55 00 05 17 39 37 00 87` (example; raw payload retained, not guessed as standard Battery Level) |
| Photo | `AB 55 00 03 22 31 53` | `AC 55 00 03 22 01 23` |
| Start video | `AB 55 00 02 23 23` | `AC 55 00 03 23 01 24` |
| Stop video | `AB 55 00 02 24 24` | `AC 55 00 02 24 24` |

Command channel: AA13 writes, AA14 notifications. Frames use SOF AB55/AC55, 16-bit big-endian length counting command+payload+checksum, and checksum = sum(command+payload) mod 256. All 8 passive-photo frames passed header, length, and checksum checks.

## Photo evidence

At 20:38:56 the client sent one photo command, followed by an AA14 capture response and photo-state event. At 20:38:58–59 AA15 emitted PHOTO_START (`0x97`), JPEG chunks (`0x98`, first chunk began FF D8), and PHOTO_END (`0x99`). The user confirmed the actual imported photo in GlassX. The diagnostic log truncated chunk contents; this run did not reconstruct or measure the BLE preview's resolution.

## Video evidence

- 20:43:30: start command response; ACTION_SYNC payload byte 2 = 1.
- 20:43:40: stop submitted 10 seconds after start submission; stop response.
- 20:43:41: ACTION_SYNC payload byte 2 = 0; file-count notification.
- No stop retry was needed. User subsequently confirmed an imported playable video. This validates the control cycle; an exact ten-second file duration requires separate media inspection.

## macOS execution constraint

Work Mode shell could compile Swift but could not access the Bluetooth controller. Running the same script in the user's normal Terminal succeeded (powered-on state, allowed authorization). No separate Codex.app was installed; ChatGPT.app already had Bluetooth permission. Do not tell the user to add a nonexistent application. The local shell also could not download GitHub/pip dependencies, so Swift with built-in CoreBluetooth was used.
